# 原生条件诊断结果与 CauPano 下一步

分析对象：`outputs/m3dlayout_native_probe_run001`，6 个原生场景、text/prefix 两模式、3 seeds，共 36 次。此次只读取生成结果、计算诊断指标和绘图，未修改推理行为，也未运行 GPU 作业。

## 结论

现有 M3DLayout 权重在部分原生条件下有可用的结构续写能力，尤其两个 3D-FRONT 卧室；不是整个输入接口都失效。但两个 Matterport 场景表现不稳定，不能据此认定适用于 CauPano 的相机可见集合补全，更不能直接把纯文本布局并入 G_obs。

当前合理路线仍是：Local RGB → 可见实例结构 + 简短可见场景描述 → 同一坐标中的条件补全候选 → 合并原始观测 → Adapter。首要改进是固定几何表示与可见集合诊断，而不是对旧三张图反复加规则。

## 接口与生成行为

- 36/36 正常生成 END，0 次异常 START，未触及解码上限。
- 18/18 prefix 数值保持不变。注意官方 complete_scene 本来就直接保留 context，这只是接口检查，不是模型学会保留物体的证据。
- 新增对象没有非正尺寸。
- prefix 新增对象合计 119；对应 GT 后半段在三个 seeds 下重复计数合计 93。数量不是质量。

IoU 采用 native 半尺寸构建旋转框，计算 xz 旋转矩形交面积 × y 交叠高度。匹配优先最大化同类且达到阈值的匹配数，再最大化 IoU。这里是原场景复原参考，不是合理布局的唯一答案：镜头外多解、薄物体位移与严格细类匹配都会影响该指标。

同类数量交集指标（不匹配位置）：prefix 新增对象中，3D-FRONT 为 12/15（80.0%），Infinigen 为 32/45（71.1%），MP3D 为 26/59（44.1%）。相应 GT 后半段数量分别为 18、45、30。不能把 text 对完整 GT 与 prefix 对剩余 GT 的指标当成同一难度的公平排名。

## 逐项证据

### 结构条件确实有帮助，但程度有限

第一间卧室已知左侧床头柜、床和灯，三个 seeds 均在床另一侧续写床头柜，衣柜也位于右侧。第二间卧室补出床上方灯和右侧衣柜，但两个 seeds 漏掉另一床头柜，灯从 pendant_lamp 变成 ceiling_lamp。

Infinigen 客厅的 text seed 1 生成 standing_sink、toilet、mirror 等浴室对象，虽然文本明确写 living room；prefix 三个 seeds 都续写了 sofa。这支持结构条件比只依赖文本更值得继续验证，但不是总体性能的统计结论。

浴室三个 seeds 新增数量都是 3，不等于正确补全。位置和关系变化很大，镜子未稳定延续在既有洗手池附近。客厅家具大类部分合理，布局也显著偏离 GT；偏离 GT 本身不等于不合理，但需要看与已知部分是否相容。

### 不能把所有重复归咎于生成器

第一间卧室 GT 的两个 wardrobe 的 3D OBB IoU 约 0.992。prefix seed 0、2 的两个衣柜 IoU 分别约 0.908、0.711。该现象至少与 GT 对象表示重叠一致；未经原始资产核查，不能直接判定为两个独立家具，或直接称为模型重复错误。不要据此加普遍去重规则。

MP3D 走廊画框空间密集，但没有发现同类框 3D IoU>0.5 的新增相关对。薄框在俯视图靠近不等于严格 3D 重复；仍应检查画框分布是否符合走廊结构。

### 官方描述也不是绝对真值

Infinigen 浴室描述提及 bathtub、shower，而原生对象列表为 large_plant_container、standing_sink、mirror、toilet、wall_art。客厅描述说没有小物品，但原生对象列表包含多件 nature_shelf_trinkets。不能同时把文本完全满足率和原生对象逐项复原都当作无噪声真值。

### Matterport 风险最值得关注

门廊/露台场景 GT 后半段只有 table、lighting、4 chairs。prefix 却补出 12–16 件，seed 1、2 出现 bed；完整描述并不要求床。走廊 text 生成数 21/2/2，结构续写虽集中到 picture，但未复原剩余画框分布。

这里的两个 MP3D 样本分别是门廊/露台和走廊，不代表 CauPano 全部室内样本。不能因结果差删掉它们，也不能由它们推断所有卧室、客厅均失败。下一阶段按任务域事先固定取样规则，并保留这次结果作为诊断记录。

MP3D 门廊输入椅子 native 底部约 y=0.78–0.86，而 seed 0 第一张新增桌子底部约 y=0.03；有明显高度分布差异。没有源 mesh/地面定义支持时，不应武断把所有对象搬到 y=0。

## 原因：已确定与未确定

已确定：

1. 当前原生续写在部分场景有效，错误不能全部归到 Qwen3-VL，因为此次没有 Qwen 输入。
2. 旧预测桥接默认 full，但官方原生 size 按半尺寸解释；后续应统一转换，而非按图片选择 full/half。此次 native 测试原样输入尺寸，不受旧桥接影响。
3. 旧相机桥接假设 camera_height=1.5、yaw=0、xz=0，不是估计出的房间配准。
4. 官方空间前缀与真实可见集合是不同的条件分布；排列相同对象不能消除这个差异。
5. 发布数据的类别、统计、描述和实例几何存在差异或噪声。

未确定：

- 新数据 103 个对象类别与 demo 101 个对象类别的差异是否影响该权重的类别语义；shape 匹配不能证明语义一致。但多个卧室表现正常也不支持“全词表彻底错位”的直接判断。
- 本地官方 sampler 使用 ELU(raw)+1.0001，loss 使用 exp(clamp(raw,min=-7))。这两个参数化并非处处相同，但未读取该权重训练时版本，也未做单变量对照，不能据此认定是本次主要错误原因。不把它与坐标、描述、采样策略同时改动。
- 官方验证场景与该权重训练数据版本的准确对应关系尚未独立确认，不能将原生场景复原表现直接解释为泛化能力。

## 方法改进与执行顺序（不训练 Completion）

### 1. 先固定两套表示之间的桥接

M3D：细类名称、room/native 坐标中的中心、OBB 半尺寸、yaw。

Adapter：既定 category_id、Local 相机坐标中心、Local 轴 AABB 完整边长、validity、padding。

从 Observer 完整框到 M3D：角点转到房间坐标 → 求适用的 upright OBB → 完整边长除以 2。输出反向：native OBB 八角点 → 同一个配准变换的逆变换 → Local 角点的 min/max → AABB 完整边长。不要把 2×native size 直接当成旋转后的 Local AABB。

保留已观察对象本身，不通过 yaw-only 包围框反向覆盖 Observer 原框。类别映射单独做，细类别给 M3D、已有 category_id 给 Adapter；不增加 Encoder 字段。

GT 配准只用于诊断。最终单图推理的相机高度、朝向和尺度必须来自该输入可获得的信息或明确记录的假设，不能偷偷使用 GT，也不能宣称任意放置相机就是恢复了房间原点。

### 2. 下一项 GPU 实验应回到真实任务的 GT 可见集合

固定现有 CauPano val 中一小批室内样本，例如当前四栋建筑各 3 张，按固定规则选取，不根据生成结果挑图。已有 native 结果保留，不再围绕旧 3 张图修补。

在可核实同一房间、同一对象集合、同一坐标变换的样本上比较：

- 与 GT 可见对象数相同的官方空间前缀。
- GT 真正可见对象集合。

两组使用相同权重、seed、文本及 room 条件。文本来自 Local RGB，不读 GT ERP；真实可见性来自已有 GT pipeline，不把简单视锥测试等同于可见性。前缀本身可能包含相机不可见对象，因此该组仅作条件分布诊断。

将单房间诊断与 ERP 可见对象全集区分。相机通过门洞看到其他房间时，不能删掉那些对象后还声称评估原来的 full ERP 目标。

如果连 GT 可见集合也持续失效，先承认官方预训练权重的免训练迁移局限。不要把错误交给 Observer 继续修补，也不要强制禁止 END 或硬补固定类别。

### 3. GT 可见条件可用，再比较预测可见条件

同一批 Local RGB、同一描述，替换为 Qwen3-VL 预测的 G_obs。采用一次可见实例枚举，再逐实例求 3D，减少 chair/armchair/seating 多轮重复；这是观察端组织方式，不是新增 Adapter 字段。优先核对实例、中心、尺度与轴约定。

让 M3D 同时接收结构和简短的可见场景描述。描述补充房间功能和可靠关系，不能替代米制几何。用户可选文本中的编辑意图与可见事实分开。

生成多个候选，完整报告固定 seeds；后续如设计自动选择，只能根据输入一致性等预先确定标准，不能用 GT 隐藏布局挑最好结果。

### 4. 两条研究线汇合

保持现有 Encoder/Adapter Oracle 训练独立。如果 Oracle 证明正确结构优于 constant/shuffled，且预测补全通过上述基本诊断，再比较 No World、Pred G_obs、Pred G_obs+Completion、GT G_full 对 ERP 的影响。Full-trained Adapter 的 observed-only 推理有条件分布差异，需单独说明。

纯文本生成保留为对照，当前结果不支持把独立文本布局直接拼进 G_obs。是否最终改善 CauPano，必须回到原图一致性、隐藏区域合理性和 ERP 质量，而不是只看布局能否导出 JSON。
