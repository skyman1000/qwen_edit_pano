## 结论

11 个成功配准房间的 native/source 对应和当前条件输入没有发现尺度、坐标或 START 切片错误。本轮最突出的现象是 GT 可见集合条件导致大量立即 END；它与已知集合包含空间排序末端高度相关，支持“官方前缀续写训练与任意可见集合补洞任务不匹配”的解释。不能声称已经通过因果对照确定唯一根因。

- 选中 11 个房间，4 栋建筑分别为 2/3/3/3 个，不是 12 个。未选原因保存在 audit.json，不需补到指定数量后重新选效果好的房间。
- 66 次全部正常 END，所有 context 保持，0 次异常 START。
- 从 raw_normalized.json 重新比较编码后的输入，全部一致；没有输入归一化分量超出 [-1,1]。
- 全部描述来自对应 Local RGB，未达到 token 上限；两个条件共享同一文本。

## END 与空间排序末端

以下 6 个场景在全部 3 个 seeds 均直接 END：

| 场景尾号 | 房间 | 可见数/原生总数 | 可见集合中的最靠后对象（0-based） |
|---|---|---|---|
| 346b680… | gym | 5/12 | 11，最后一个 |
| 445ae020… | family room | 4/14 | 12，倒数第二个 |
| 3b3649d2… | spa | 7/14 | 13，最后一个 |
| ead48153… | bedroom | 16/21 | 20，最后一个 |
| ed864538… | living room | 14/30 | 29，最后一个 |
| 5e966f4b… | bedroom | 8/12 | 11，最后一个 |

所有包含原生最后一个对象的可见集合都立即 END，此外一个含倒数第二个对象的场景也如此。三个 seeds 的一致现象支持终止偏向，但文件没有保存 END 概率，不能报出其概率或称为确定性规则。

官方 dataset 先按离散化 x,z,y 排序，再用 `v[:n_boxes]` 作 context、`v[n_boxes]` 作目标。它没有在此训练路径中教授“保留后部可见对象，同时补前部缺失对象”。当前 `_encode` 的对象 token 没有序号位置编码，空间位置编码是几何数值编码。因此简单把相同可见对象倒序/打乱不构成任务适配，原理上也不会消除集合内容带来的差异。

END 类别先由 class_layer 采样，之后才执行几何 DMLL 采样。因此之前发现的几何采样尺度参数化差异不能直接解释固定 context 下第一步就 END；本轮不应优先改几何 sampler 或强行屏蔽 END。

## 仍存在的任务范围问题

原 G_obs 共 131 个对象，实际 native 可见条件仅 83 个（63.4%），48 个未进入。按记录其中 28 个属于主房间之外，其余为主房间内不在 native inventory 的对象。

特别是：

- `x8F5xyUWy9e_03de84…`：原观测 14，模型条件只保留 1；其中跨主房间 12。
- `x8F5xyUWy9e_27b836…`：原观测 11，模型条件只保留 1；其中跨主房间 6。

两张图的描述包含 Spa 或通过门口看见的浴室信息，而结构只代表相机所属主房间的一小部分。文本与布局目标范围不完全一致，是独立干扰因素。不能把这两个样本的失败全部归因于条件分布，也不能修改统计删除它们；应按观测覆盖率分组解释，保留完整记录。

这也说明“以相机 region_id 对应单个房间”的简化不足以覆盖最终 ERP 任务。多房间观测仍需保留在最终世界中；单房间补全的对象范围必须与文本范围明确对应。

## 哪些地方需要改，哪些不应继续改

1. **保留已核实的几何桥接和字段定义。** 本轮不支持继续调 full/half、相机高度、轴符号或放宽匹配阈值。旧预测桥接的 1.5m 假设不因此变成已验证，预测条件未来仍需真实可得的配准估计。
2. **固定当前 11 个样本，停止扩充 seeds 来找好结果。** 本轮足以暴露立即 END 的系统性现象，下一步无需重复全部 66 次布局生成。
3. **如需进一步定位，只做一次起始条件诊断。** 在现有权重中读取首步 END 概率/top classes，对每个同一场景比较 prefix 和 visible，再比较 visible 中末端对象被同数量较早已知对象替换的诊断条件。修改 context 会改变信息，不能称为严格独立因果证明；不要把这个替换用于最终方法。也可用 permutation 检查验证相同集合重排不产生显著 logits 变化。该入口尚未实现，本报告不提供虚构执行命令。
4. **在不训练的约束下，当前官方续写器不应成为最终补全主链的必需环节。** 将它保留为对照；主线资源优先放回 Oracle 世界条件是否有效，以及可靠的 Observer/坐标几何。Predicted G_obs-only 的下游推理可作诊断，但 Full-trained Adapter 有条件分布差异，不能当公平训练消融。
5. **若研究目标必须保留 hidden completion，则需真正支持任意观测集合的方案。** 可以另行验证预训练模型或推理方法，但必须证明能在同一坐标保留全部观测并补缺失部分，而非仅有 text-to-layout 或 prefix completion 接口。任何新候选仍先过 GT-visible 测试，不承诺换模型即有效。
6. **未来用户允许训练时才考虑采样策略适配。** context=全部 observed+已生成 hidden，target=下一个 hidden/END；这属于训练分布改动，当前不执行、不要求用户启动。

不推荐立即屏蔽 END、强制最少生成数、删除末端已观察对象、用重新排序冒充适配、或将纯文本布局直接拼到 G_obs。这些操作会掩盖停止现象或破坏任务约束，尚无证据能恢复缺失结构。
