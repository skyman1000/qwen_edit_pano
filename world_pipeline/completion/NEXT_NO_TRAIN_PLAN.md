# CauPano 免训练 Completion 下一步方案

2026-10-11。当前约束：Completion 不训练；现有 Encoder/Adapter Oracle 实验独立进行；GPU 工作由用户手动执行。第一步数据审计与第二步原生诊断现已实现，运行方式见 [NATIVE_PROBE.md](NATIVE_PROBE.md)；后续步骤仍是设计，不代表入口已经实现。

## 研究目标

局部 RGB + 可选文本 → 与局部观察相容的候选对象世界 → 冻结 Qwen-Image-Edit + 已训练 World Branch → ERP。当前待回答的是官方 M3DLayout 权重是否可免训练用于缺失对象补全，而非在三张图上调出漂亮布局。联合框/文本是候选路线，尚未证实有效。

## 立即停止重复的实验

保留 run001，不继续改文本长短、挑 seed、强制禁止 END、对生成物体按类别贴地或删除。不将纯文本独立布局直接并入 G_obs。Full/half 尚未核实，不用三张图哪种好看来决定每张图用哪种。

## 第一步：取得官方布局 JSON，核实数据约定

官方仓库： https://github.com/Graphic-Kiliani/M3DLayout-code
布局包： https://huggingface.co/datasets/Metaverse-AI-Lab/M3DLayout/tree/main/layout_dataset
文件：layout_dataset/M3DLayout_json.zip，页面显示约 32.5 MB。只需布局包，不下载 scene_dataset / rendering_dataset。

读取包内实际文件后，核对与现有 autoregressive_59000.pth 配套的类别顺序、归一化统计、坐标轴、原点、单位和 size 定义。不能因为模型 strict load 成功就断言类别顺序一致。若发布数据与权重训练版本无法对应，必须保留这个未决项。

用能够与已有 Matterport 原始 OBB/物体几何对应的对象，检查 JSON size 的独立物理含义。normalize→denormalize 自己往返能通过，不足以证明尺寸含义正确；错误的乘2/除2也能互相抵消。地面残差支持 half 但也不是独立真值。

另记录本地官方 sampler 的 ELU(raw)+1.0001 与 DMLL loss 的 exp(log_scale) 差异。原始采样器保留作基准，若验证修正采样器则单独标识，不能把采样器、尺寸与文本同时修改。当前发布源码不一定就是权重训练时版本，不能未经核实认定该差异解释了所有错误。

产出：固定一份权重/统计/词表/单位说明；若仍未知则明确列出，而不继续把米制生成当成已校准结果。

## 第二步：官方原生条件诊断

从官方布局数据固定选少量场景，例如6个，沿用其原坐标和类别。固定3个seed，不使用Qwen。

A. 官方场景描述 → 从头生成。
B. 按官方排序规则取已知对象前缀 + 同一描述 → 续写。

首先确认类别、合理量级、EOS行为及与原生 context 的相容性。原生完整描述可以用于这里的实现诊断，但可能包含隐藏对象信息，不能计为最终任务的图像条件补全结果。

如果 A/B 都明显异常，先排查权重与统计/词表/采样实现；不修改 Observer。若有公开样例做比较，比较正常工作模式而非要求随机结果逐对象一致。

## 第三步：隔离可见集合和目标范围差异

在具有真实可见性与原始 OBB 的 Matterport 样本中，保持类别/几何/文本相同，仅比较：官方空间前缀 context 与真实可见对象集合 context。排序同一组可见对象不等于把它变成训练前缀。

区分 room layout 与 ERP-visible object set。先将单房间、原生坐标的实验作为诊断，再检查跨房间 ERP 对象范围；不能静默删掉非主房间 GT 后仍宣称补全了原来的 G_full。最终 ERP 目标集合保持不变。

GT 诊断应使用源 OBB/真实可获得的变换。不要用已经丢失朝向信息的 local-axis AABB 假装恢复原始 OBB。不要仅把 GT AABB 填入旧 1.5米假设桥接，就称几何误差已经被排除。

结论分支：原生前缀正常、真实可见集合失败，支持任务分布不适配；不应继续靠长描述补救。若真实可见集合也正常，再进入预测 Observer。

## 第四步：免训练 Observer 改进及成对测试

固定相同新验证图，分别输入 GT 可见结构和 Qwen 预测结构。文本统一来自对应 Local RGB，不读目标 ERP/隐藏对象。每栋固定3张可作为12张诊断集（当前4栋val），排除旧调试三图，按建筑和固定seed抽取后锁定；不以生成效果筛图。该集合用于开发诊断，正式性能仍需保留其余验证样本。

Observer 采用一次可见实例枚举（instance_id、2D box、类别）→ 用2D实例提示查询3D框。同一实例只问一次。保留官方细类名称供 M3D，用独立category_id映射供Adapter。仅合并同义类别不能处理chair/seating/furniture全部实例重叠。先核实Qwen原生9DoF坐标与角度约定；不把所有旋转强行当成可精确恢复的yaw。

评估：可见实例遗漏/重复、类别、匹配对象中心/尺寸误差，以及投影与原图的粗一致性。单纯位于视锥内不等于应该删除；遮挡后仍可能是合理新增对象。

只有GT-observed正常、预测observed明显差，才优先投入Observer改进。GT和预测都差，不应把原因直接归给Observer。

## 第五步：固定协议比较文本作用

仅比较 room hint 与简短结构描述。使用相同观测/桥接/采样器/seed，保持text_condition=true。描述只含可见场景功能、主要家具及可靠关系。描述的观测事实与用户期望分开，不能把用户想添加的对象冒充已观察对象。

报告：输入对象保留、未进入模型的类别比例、过早END/容量结束、新增对象与原图冲突、尺寸合理性、GT隐藏对象类别及几何参考指标、跨seed多样性。GT IoU不是多解合理性的唯一标准；生成数量更多也不是更好。单个seed最好结果不能代替全部结果。

## 第六步：与Qwen-Pano的研究问题汇合

只有独立Oracle结果支持正确世界状态有效，且预测结构具备基本可信度时，才做同一图像/文本/seed的：无World、Observed-only、Observed+Completion、GT Full参考。当前Full训练Adapter面对Observed-only仍有输入分布差异，这组是推理诊断，不能等同于训练条件匹配的Observed-vs-Full消融。

评估前向局部保真、隐藏区域结构、ERP整体质量和接缝。保持原始Local RGB输入。预测图推理接入当前仍需实现，不伪造已有命令。

## 止损条件

在表示核实及一次固定原生/GT/预测诊断后：若官方权重在原生条件正常，但真实可见集合持续失败，结论应是当前免训练迁移不成立，不继续针对旧图叠加规则。用户不训练的约束不变，可将M3D保留为语义生成对照，并把资源优先放回既有Oracle结果和可观测结构路线；替代模型也必须证明支持所需条件，不能仅凭text-to-layout宣传换模型。
